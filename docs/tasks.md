# 任务工作台

### 通用工作任务

先发送 `/工作 开`。之后直接描述任务，例如：

```text
检查 /path/to/project 的问题，修复并运行相关验证。
把修改说明写成 Markdown，把测试数据写成 CSV；需要的图表也一起发给我。
```

消息中的换行、代码和 `@文件` 参数会保留；同一条消息附带的 QQ 图片或文件会下载到任务目录，供执行器读取。
也可以继续使用 `/任务 <内容>` 单次执行，或者用 `/工作 关` 返回聊天模式。

| 指令 | 行为 |
| --- | --- |
| `/任务 /超时7200 <内容>` | 指定时限，默认 30 分钟，当前配置最高 24 小时 |
| `/任务 /超长 <内容>` | 默认 60 分钟 |
| `/任务列表` | 查看当前用户在当前会话的最近任务 |
| `/进度 [任务号]` | 查询状态、耗时、当前步骤、发送成功及待发送数量 |
| `/取消 [任务号]` | 取消排队任务，或终止执行任务及其进程组 |
| `/继续 [任务号] [补充要求]` | 在前次上下文中检查已有成果，再执行一项新任务 |
| `/日志 [任务号]` | 最近的工具执行情况和主动报告的进展 |
| `/结果 [任务号] [页码]` | 分页查看完整正文，包括代码和表格文本 |
| `/适配 <任务号> <序号> [MiB]` | 后台分段视频，默认每段 20 MiB，必要时转码 |
| `/下载 <任务号> <序号>` | 在已配置下载站点生成原文件链接 |
| `/全文 [任务号]` | 将完整正文作为 Markdown 文件发送 |
| `/文件 [任务号]` | 列出产物及序号 |
| `/文件 [任务号] <序号>` | 发送对应产物 |
| `/预览 [任务号] <序号> [页码]` | 在 QQ 中查看 CSV、JSON、代码、Markdown 等文本附件 |
| `/补发 [任务号]` | 重试该任务仍未送达的消息与附件 |
| `/目录 [绝对路径]` | 查看或设置后续任务的工作目录 |
| `/新会话` | 后续任务使用新上下文，保留历史结果 |
| `/聊 <内容>` | 在工作模式下临时闲聊 |
| `/帮助` | 查看指令 |

省略任务号时使用最近任务。例如 `/进度`、`/取消`、`/结果`。
指定页码或文件序号时，请使用完整形式，如 `/结果 abc123def456 2`。
这些工作指令沿用 `agent_allowed_openids` 授权名单；群聊与单聊的身份标识可能不同，
应把实际授权用户的对应标识写入配置。群聊成员不会共享执行上下文或任务查询权限。

## 执行与反馈

- 任务先写入 SQLite，再由默认两个 worker 执行；相同会话上下文串行，队列默认最多 30 项。
- 普通聊天与任务控制分开处理，聊天模型耗时不会堵住 `/进度`、`/取消` 或新任务登记。
- pi 使用 JSON 事件流；默认约一分钟给一条进展提示，之后可随时主动查询，避免高频消息耗尽回复次数。
- 正文完整保存在 `state/tasks/<任务号>/result.md`，默认自动发送第一页，其他页随时可取。
- 产物位于每项任务的 `artifacts/`，完成时默认自动发送前两个；其余通过 `/文件` 取回。
- 图片、视频、音频和普通文件分别按 QQ 的媒体类型上传。PDF、ZIP、CSV、HTML、代码等可作为普通文件交付；
  QQ 是否接受具体格式、大小和会话场景，以实际接口响应为准。文本附件还有 `/预览` 通道。
- 发送成功必须收到 QQ 消息 ID。失败记录在持久发件箱里，`/进度` 可见原因。
  网络短暂故障有界重试；回复机会过期时，下一次同一用户在同一会话的互动会恢复待发内容。
- 不对已发送内容盲目重发。主动消息的响应丢失时，无法确认是否送达，保留为待处理，由用户查询或手动补发。
- 重启后恢复排队任务。正在执行的任务标记为“执行中断”，保留部分正文及产物，使用 `/继续` 核对后继续；
  **不承诺服务重启后原进程不断运行，也不自动重放可能已有外部影响的任务。**

QQ 的主动消息权限、回复窗口及媒体能力是平台边界。当前采用保守的 240 秒回复窗口和每条消息 5 次回复预算，
可以按实际账户能力配置；这些是本项目的默认策略。保持窗口开放不等于平台允许无限主动推送。

## 给执行器的文件反馈能力

每项任务会自动获得 `AKARI_TASK_DIR` 和 `AKARI_OUTPUT_DIR`。执行器可直接把最终产物保存到后者，
也可使用下面的本地 helper 登记已完成的文件，在任务结束前交付：

```bash
python3 /path/to/Akari-Bot/akari_report.py progress "已完成数据清洗，正在生成图表"
python3 /path/to/Akari-Bot/akari_report.py file /绝对路径/report.pdf
```

helper 将其他目录的文件复制到独立产物目录，再登记到反馈流。它不持有 QQ 凭据，不直接发送 QQ 消息。
本地上传默认上限改为 512 MiB（`agent_upload_max_bytes`），这不是 QQ 官方单文件限制。
本地文件默认使用官方分片上传：申请 → HTTPS PUT → 分片确认 → 完成上传 → 发送消息。
上传按块读取，默认至多两片并发且服从服务器返回的并发数；分片进度持久保存，补发可复用已确认分片。
`/进度` 可查看已上传字节和分片数。文字和媒体各有一个发送线程，附件上传不会占住查询回复。
兼容模式 `agent_chunked_upload=false` 只允许 1 MiB 内的 Base64 上传，避免大请求体。
文本预览默认不超过 2 MiB，接收附件默认每个 20 MiB、每条消息最多 10 个；这些与发出文件的限制独立。

`agent_video_auto_adapt=true` 可在符合条件的大视频上传被拒后创建分段交付任务。默认阈值是本项目策略，不代表 QQ 官方上限。具体可上传大小以账号和平台响应为准。

也可输入 `/适配 任务号 文件序号 20`，主动生成每段不超过 20 MiB 的独立 MP4。
优先按关键帧保留原编码；仍超限的片段转码，可能降低画质，原文件保留。
该操作由后台进程执行，支持 `/进度`、`/取消`，不依赖模型临时编写转码命令。
生成文件仍需 QQ 接受格式、大小和发送额度。日上传额度耗尽时，分片或分段均不能绕过。

下载外链为可选功能：管理员将 `agent_download_root` 设置为现有静态站点目录，
将 `agent_download_base_url` 设置为该目录对应的外网 HTTPS 地址，重启服务后可用 `/下载`。
它只复制用户选中的文件，使用随机文件名，不启动公网服务，不自动安装隧道。
链接持有者可下载，默认不自动过期；管理员负责站点可达性、访问策略和过期文件清理。
尚未配置站点时会明确提示，不会伪造外链。

后台 pi 通过项目内的 `akari_context.mjs` 加载独立上下文保护，不改全局 pi 或模型网关。
新 QQ 任务将完整旧任务记录归档为可读 JSON，保留历史要求、摘要、最终文字与归档路径，避免跨任务无限累积；原会话文件保持完整。
默认每轮保留最近两张图片、最大输出 16384 tokens；工具长文本节选，其完整内容和历史图片
存入任务的 `context-cache/`，供按需读取。最终请求同时限制文本预算，保留工具调用/结果配对。
同一任务内，请求接近字节预算时也会成组归档已完成的工具调用与结果，保留最近步骤，
并提供 `context-cache/steps-index.json` 和原文路径供回查；未完成的并行调用不会拆散。
这是 bot 的历史归档保护，与 Pi 按 token 用量触发的自动摘要压缩不同；Pi 自动压缩保持开启。
`context-cache/budget.jsonl` 记录每轮图片数量、文本预算、归档组数及各角色/工具定义的大小。
若归档后用户指令或尚未完成的调用仍超过预算，会明确报告剩余大小和记录位置。
保存的任务正文和用户要求不会被静默丢弃。
执行能力来自现有 pi、本机软件与运行账户权限；工作入口没有固定任务类别白名单。
