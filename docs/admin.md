# 灯里控制台

中文响应式页面，无前端构建步骤、外部字体或 CDN。默认地址 **http://127.0.0.1:18763**。

## 启动与登录

在仓库根目录运行：

```bash
python3 akari_admin.py --port 18763
cat state/admin/access.token
```

启动时自动生成独立访问口令，仅所属用户可读；登录会话有效期 12 小时。重启管理服务会清除会话。QQ 密钥和模型 API Key 不会返回配置接口。

仅监听本机，另一台电脑可通过自己的 SSH 连接映射**相同的本地和远程端口**：

```bash
ssh -N -L 18763:127.0.0.1:18763 <登录用户>@<Bot服务器>
```

在本地浏览器打开同一地址。Host 校验只接受 `127.0.0.1:<端口>` 和 `localhost:<端口>`；默认不支持直接通过公网 IP 或自定义域名访问。

## 六个页面

| 页面 | 操作 |
| --- | --- |
| 运行概览 | 进程状态、QQ 网关、已保存的功能数量、执行/排队数、最近任务 |
| 功能管理 | 工作台、图片理解、搜索、表情、图片、视频、语音和翻唱开关 |
| 参数配置 | 对话、媒体、语音/翻唱、任务、连接五类参数 |
| 任务记录 | 最近 40 条、状态筛选、指令、时间与错误详情 |
| 运行日志 | Bot、进程输出、管理操作；关键词/级别过滤、暂停、跟随、复制和下载 |
| 系统诊断 | 启动/重启/停止 Bot、本机依赖端口检查、GPU 显存与利用率 |

## 保存与生效

1. 修改后出现底部保存栏，跨页面保留草稿。
2. “保存修改”会校验类型、范围及关联限制，备份原文件后原子替换；保留未知字段与密钥。
3. Bot 配置需“应用并重启”。音乐内部参数由下一次任务读取；当前任务保持启动时参数。
4. 其他窗口或程序修改配置后，过期保存会被拒绝。使用“撤销修改”重新载入再编辑。

Bot 与音乐配置按文件分别保存，跨文件不是单个事务。一个保存成功、另一个失败时，未保存部分仍保留提示。外部程序写入配置时，应避免与控制台同时操作。

备份：`state/admin/bot-时间-随机值.json`、`state/admin/music-时间-随机值.json`。备份可能含密钥，不能上传到仓库。页面不提供自动恢复，需由管理员核对并恢复需要的配置。

## 状态与日志的含义

`state/runtime.json` 每 5 秒记录 PID、启动时间、网关状态与配置指纹。只有数据新鲜、PID 与 systemd 一致，页面才认定网关状态有效。手动启动时 systemd 状态可能未知，不表示 QQ 一定断线；请结合 Bot 日志确认。

服务控制仅针对 `akari-bot.service`。排队或执行任务存在时拒绝重启/停止；空闲检查到操作结束之间持有队列写锁。普通聊天和自动媒体回复不在长任务队列中，仍可能被重启中断。

日志最多读取文件尾部 512 KiB，显示筛选后最近 300 条。错误级别依据关键词推断，保留多行堆栈；已知凭据和常见 token 字段会脱敏。日志仍可能含聊天内容和文件路径，下载后请按用户数据处理。

依赖诊断只验证本机端口能否连接，不证明模型质量或所有 API 正常；不会生成音频、图片或 QQ 消息。GPU 信息通过 `nvidia-smi` 按需读取。

## 口令与服务维护

按 [部署文档](deployment.md) 安装独立管理服务后，可使用：

```bash
sudo systemctl restart akari-admin.service
sudo systemctl status akari-admin.service
```

如需更换访问口令，先停止管理服务，再删除 `state/admin/access.token`，启动后会重新生成。不要删除整个 `state/`。

管理接口具备会话鉴权、登录限速、HttpOnly/SameSite cookie、CSRF、Origin/Host 校验与静态文件白名单；不提供任意 shell 执行入口。
